familiar is a folder. Download it, rename it to your project's name, and open your AI coding assistant
inside it. The folder holds what the project is, what has been decided, what is open, and where the
source for each claim lives, so every session starts from that record instead of from nothing.

<CardGrid>
  <Card title="Nothing explained twice" icon="document">
    Status, tasks, decisions and handoffs live as Markdown beside your work. A new session reads them and
    picks up where the last one stopped.
  </Card>
  <Card title="Answers from your sources" icon="magnifier">
    Ingested documents become cited pages with a locator on every claim, so answers trace back to your
    own files rather than the model's memory.
  </Card>
  <Card title="One folder per project" icon="seti:folder">
    Each project keeps its own memory and stays out of the others. Confidential material stays inside the
    project it belongs to.
  </Card>
  <Card title="Yours, on your disk" icon="open-book">
    Plain Markdown and a few small scripts. No account, no server, nothing running in the background.
  </Card>
</CardGrid>

## Across all your projects

The optional [fleet hub](https://github.com/familiar-md/familiar-hub) reads every project and writes
you a daily brief: what is overdue, what lands in the next two weeks, and what you can start today.

<img src="/familiar/assets/fleet-brief-example.png" alt="The fleet hub's daily brief, built from fictional projects" width="750" />

Built and tested with Claude Code. familiar follows the open `AGENTS.md` and agent skills conventions,
so other assistants that read them should work too.
